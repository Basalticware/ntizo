What changes

The person sends us the code, instead of us sending it to them

There is no SMS provider, so the code can never arrive by SMS. Here the direction flips: the screen gives the person a code, WhatsApp opens with it already typed, and they tap send. Meta tells our API who sent it. WhatsApp has already verified that sender's number, so a matching code proves the number belongs to the person. Nothing is paid: Meta does not charge for messages a user sends, and our reply falls inside the free 24-hour window.

  • Invited once, never forced

    The email confirmation link now lands here first, with "Agora não" to carry on. Anyone with no number (Google sign-up) or an already confirmed one skips straight past. Conta → Segurança → Verificar still leads here.

  • One code, 15 minutes

    Six digits, tied to the account and to the number it was issued for. If the number changes in between, the code no longer confirms anything.

  • The page notices by itself

    While waiting it checks every 3 seconds and the moment the person switches back from WhatsApp, reading the session past its 60-second cookie cache.

"Agora não" only appears when the page was reached as an invite (it carries ?next=). Reached from Conta → Segurança, the same spot reads "Voltar à conta".

"Alterar" goes to the profile form, where the number is edited today. Changing it clears the confirmation, which the profile already does.

The other failure (WhatsApp not configured on that stage, or the network) uses state 4's layout with "Não foi possível começar agora. Tente dentro de momentos." and a retry. A message sent from a different number is answered inside WhatsApp, where the person is at that moment, so the page simply keeps waiting.

The Ntizo number and "até 14:52" come back from the API with the code, so the page never hard-codes the number.
